Automated machine learning (AutoML) libraries such as FLAML can find a good model and its hyperparameters within a time budget. What they leave to the user is the work around the search: finding out why a model is weak, deciding what to change in the data or the settings, checking whether a change really helped and deciding when to stop. In this project we built AutoPilot-ML, an autonomous experimentation layer that takes over this whole loop for tabular data. It runs on an ordinary laptop, fully offline, and uses FLAML as its search engine.

After every experiment, a Critic looks for weaknesses such as overfitting, class imbalance or misleading high-cardinality columns. It knows 14 kinds of diagnosis and bases each one on evidence measured on 15 fixed folds of the training data. A Strategy Engine then proposes one of 12 changes, and a Judge keeps the change only if a corrected resampled t-test on the same folds shows that it is better, or that it is simpler and not worse. A Resource Manager shares out the time budget and decides when to stop. An Experiment Memory keeps every change with its effect and cost, and Thompson sampling uses this record to choose which changes to try first on a similar dataset. The system can be used through a Streamlit dashboard, a command line, a local web API or a Docker image, and it is checked by 586 automated tests.

We first tested the two decision components on data where the right answers were known. The Critic's data-level diagnoses never raised a false alarm, and the Judge accepted none of 18 harmful changes. We then ran a benchmark of 390 runs on 6 public OpenML datasets, in which AutoPilot-ML made good use of a larger budget: between 2 and 5 minutes its score rose on 5 of the 6 datasets, and its average rank among five systems moved from fourth to second. At 5 minutes it matched FLAML alone within the statistical intervals while using 29% less time, did better than AutoGluon and a LightGBM baseline with default settings on most datasets, and gave the best score of all systems on the imbalanced pc4 dataset. The outcome is a working, tested system that runs fully offline and explains, records and can repeat every decision it makes.

**Keywords:** automated machine learning, FLAML, autonomous experimentation, corrected resampled t-test, multi-armed bandits, tabular data.
